# Проверка клиента

## Версия 1.0.3 — 10 октября 2026

- TypeScript, **75 unit/integration тестов** и сверка 37 палитр, их ленивых файлов и превью с оригинальными алгоритмами — успешно.
- Добавлены браузерные сценарии: отсутствие периодического опроса и «Обновляем…», восстановление SSE без дублирования текста, доступ к сессиям при отказе провайдерного endpoint, задачи из событий без HTTP-перезагрузки, iPhone-only Liquid Glass, режим уменьшенной прозрачности, гонки загрузки/сохранения темы и скрытие пустых рассуждений. Полный набор — **87 сценариев**; обязательный прогон — job Protocol + browser checks в GitHub Actions перед публикацией.
- Windows bootstrap `--minimal-powershell` — успешно: установка/обновление, SHA-256, автономный CLI, JSONC, команды и TUI.
- Основной production JS-файл: **~237 КБ** против ~1422 КБ до разделения палитр (до gzip, сравнение размера файла, не замер FPS/старта на телефоне). Полный каталог не импортируется в стартовый бандл. Все файлы тем входят в APK/IPA для офлайн-переключения.
- iOS 26+: нативные пассивные `UIVisualEffectView`/`UIGlassEffect` под WebView-панелями, над нативным градиентным фоном. Позиции обновляются при изменении размеров/раскладки, без постоянного кадрового цикла. На ранних iOS — CSS; при Reduce Transparency/Low Power Mode — плотные поверхности.
- Swift-компиляция, сборки APK/IPA и Android lint проверяются jobs iOS и Android релизного workflow. Физический iPhone и поведение native glass после установки требуют отдельного теста на устройстве.
- Подтверждённые ограничения: текст рассуждений отсутствует в части ответов самого OpenCode (проверены длины полей API, без чтения содержимого); клиент не может восстановить непереданный текст. Пустые блоки скрываются, пояснение показывается один раз на диалог.
- Аудит сохраняет предупреждения о крупных функциях/файлах; полный рефакторинг этих модулей в выпуск не входит. Вложение сохраняется в памяти процесса, текст — в native-хранилище. Остановка процесса требует повторного выбора вложений.

### Границы поведения

- Поиск сессий и запросов работает по загруженным данным; глобальный список API сейчас ограничен 200 сессиями. Поиск по диалогу — по загруженным сообщениям, более ранние можно догрузить. Поиск файлов выполняется на сервере по проекту, до 100 результатов.
- Текст черновика сохраняется через защищённое хранилище в native-клиенте. Вложения и состояние отправки сохраняются между экранами и сессиями **в памяти работающего приложения**. После полного завершения процесса вложения нужно выбрать заново. Browser preview хранит данные только в памяти.
- Модель/режим и фильтры списка сохраняются при навигации в текущем подключении; переключение компьютера изолирует состояние.

## Нативные сборки

- **Android release APK собран локально** (`assembleRelease`, JDK 21) и проверен `apksigner`: `android/app/build/outputs/apk/release/app-release.apk`. Подпись APK Signature Scheme v2, RSA 3072.
- **Android native smoke пройден на эмуляторе API 35**: нативный HTTP и pairing, Keystore AES-GCM с длинной Unicode-строкой и проверкой шифротекста на диске, открытие клавиатуры и доступность отправки, native SSE, уведомление об ожидающем вопросе при свёрнутом приложении, восстановление подключения после полного перезапуска процесса.
- iOS-проект синхронизирован; нативная компиляция Xcode в этой Windows-сессии не выполнялась. Её нужно проверить на macOS. iOS/WebKit проверяет только интерфейс и браузерное поведение.

Релизные Android и iOS собираются отдельными job в [Build OCC](https://github.com/HVHBIGNAME/OpenCodePocket/actions/workflows/build.yml). Tagged run является источником публикуемых APK/IPA; локальный debug APK не заменяет проверку подписанного релиза.

Физический iPhone не подключался. WebKit viewport проверяет браузерный слой, но не заменяет запуск IPA на устройстве. Доставка APNs требует Apple-подписи и ключей владельца; без них end-to-end APNs не проверяется. Реальное качество распознавания речи зависит от оборудования и языкового пакета.

Не вызываем реальных AI-провайдеров в CI: протокол проверяется воспроизводимым fixture, а native smoke — отдельным Android-эмулятором. Проверка конкретного платного провайдера выполняется пользователем после подключения своего OpenCode.
