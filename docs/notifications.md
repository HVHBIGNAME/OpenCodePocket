# Уведомления и диктовка

## Android

В OCC → Настройки → Уведомления разреши системные уведомления. На Android 13+ появится системный диалог. OCC запускает **foreground service типа remoteMessaging** с постоянной карточкой подключения. Сервис самостоятельно читает SSE даже когда WebView не на экране.

Запросы `question.asked`, `permission.asked`, их `v2` варианты и `session.error` создают уведомления. Нажатие открывает нужную сессию; обработанные вопросы убираются. Текст промптов, команды и API-ключи не показываются на экране блокировки.

Поддерживается одно активное подключение. Сохранить несколько серверов можно, но фоновый слушатель относится к выбранному. Для отключения сервиса выключи уведомления или забудь активное подключение.

Force stop, перезагрузка устройства, ограничения фоновой работы или агрессивное энергосбережение производителя могут остановить сервис. Открой OCC снова для восстановления. Приложение не обходит эти ограничения скрытыми автозапусками.

## iOS

Обычная SSE-сессия не является допустимой бесконечной фоновой задачей iOS. Пока OCC открыт, работает SSE и локальная обработка событий. Для доставки при закрытом/приостановленном приложении нужен **APNs** либо внешний канал **ntfy**.

### APNs прямо в OCC

1. В Apple Developer включи Push Notifications для App ID `dev.hvhbigname.occ` (либо своего ID).
2. Создай APNs Authentication Key (`.p8`), запомни Key ID и Team ID.
3. Подпиши приложение профилем этой команды. `ios/App/App/App.entitlements` — шаблон; подключи его в Signing & Capabilities. Для distribution укажи `aps-environment=production`.
4. В окружении процесса OpenCode/standalone-моста:

```dotenv
OCC_APNS_KEY_FILE=/absolute/private/path/AuthKey.p8
OCC_APNS_KEY_ID=YOUR_KEY_ID
OCC_APNS_TEAM_ID=YOUR_TEAM_ID
OCC_APNS_TOPIC=dev.hvhbigname.occ
OCC_APNS_PRODUCTION=0
```

`OCC_APNS_PRODUCTION=1` — production, `0` — development/sandbox. Перезапусти мост после изменения окружения. Ключ `.p8` остаётся на компьютере, не включается в мобильное приложение или GitHub.

5. В OCC включи уведомления. Приложение получит device token и зарегистрирует его у моста. Настройки покажут, что APNs доступен.
6. «Тест push-канала» отправляет проверочное событие во все настроенные каналы. Посмотри логи моста, если сообщение не пришло: Apple отдельно подтверждает/отклоняет доставку.

IPA из Releases не подписан Apple-сертификатом и не активирует APNs сам по себе. Бесплатная sideload-подпись обычно не даёт entitlement remote push.

### ntfy

Мост также может публиковать generic-уведомления в твой ntfy topic:

```dotenv
OCC_NTFY_URL=https://ntfy.sh/YOUR_PRIVATE_TOPIC
OCC_NTFY_TOKEN=OPTIONAL_ACCESS_TOKEN
```

Подпишись на topic в приложении ntfy на телефоне. Уведомления содержат deep link `occ://session?id=...`. Для self-hosted ntfy на iOS учитывай upstream push forwarding из документации ntfy: без него iOS может задерживать доставку. Используй аутентифицированный topic, если сервер это поддерживает.

Сервис OCC не хранит историю push на внешнем сервере сам; ntfy действует согласно твоей конфигурации. В payload — тип запроса и ID сессии, без исходников или текста промпта.

## Диктовка

- **Android 12+**: строгий локальный режим через `createOnDeviceSpeechRecognizer`, если системный сервис поддерживает его. На Android 8–11 можно явно отключить «Только на устройстве» и использовать системный распознаватель.
- **iOS 15+**: `SFSpeechRecognizer` с `requiresOnDeviceRecognition=true`, когда язык поддерживается.
- Требуются разрешение на микрофон, а на iOS — также Speech Recognition. Установленный языковой пакет зависит от устройства и OS.
- Если локальное распознавание недоступно, OCC показывает ошибку. Автоматической отправки аудио в облако нет.
- С выключенным «Только на устройстве» системный сервис может использовать сеть. Аудио не передаётся через OCC-мост; на сервер OpenCode отправляется только текст после нажатия «Отправить».
- Частичный результат появляется в черновике. Нажми микрофон ещё раз, чтобы закончить, проверь текст и отправь.
