# Автоматические отчёты OCC

## Куда попадают ошибки

```text
Android / iOS / browser
  → ограниченная очередь отчётов на устройстве
  → POST /occ/reports через авторизованное соединение с твоим мостом
  → reports.json на компьютере
  → GitHub Issues с меткой occ-client-report
```

По умолчанию используются Issues репозитория **HVHBIGNAME/OpenCodePocket**. GitHub-авторизация находится **только на компьютере**. В APK/IPA нет GitHub-токена и возможности анонимно создавать Issues.

На ПК нужен авторизованный GitHub CLI:

```sh
gh auth login
gh auth status
```

Мост использует текущую авторизацию `gh`. На машине владельца проекта HVHBIGNAME это уже настроено. На другом компьютере можно авторизовать GitHub CLI либо передать серверную переменную `OCC_REPORTS_GITHUB_TOKEN` (fine-grained token с Issues: write для выбранного репозитория). Клиент не получает этот токен.

Если авторизации нет, отчёты **сохраняются локально**, а настройка диагностики показывает причину недоставки. Повторная отправка выполняется автоматически. Отсутствие GitHub не мешает чату и работе OpenCode.

## Что собирается

- Версия OCC, Android/iOS/web, версия OS для нативных сбоев.
- Категория: запрос API, действие, необработанное JS-исключение, запуск, native crash.
- Уровень, техническое имя исключения, ограниченный список позиций в коде.
- Название экрана и операции из фиксированного списка, HTTP-статус при наличии.
- Время отчёта и случайный ID конкретного отчёта для устранения дублей.

**Не передаются:** исходный текст exception.message, промпты, ответы модели, содержимое файлов, API-ключи, заголовки авторизации, серверные URL, имена пользователя, IMEI, рекламные или постоянные идентификаторы устройства. Backend принимает только строгую схему; неизвестные поля отклоняются.

В stack сохраняются названия модулей и номера строк/смещения, а не содержимое кода или полный путь на компьютере. Для разбора minified JS можно воспроизвести bundle по тегу релиза с source maps (`npx vite build --sourcemap hidden`).

## Ошибки запуска

- JS: `window.error`, `unhandledrejection` и React ErrorBoundary, включая ошибки раннего рендера.
- Android: собственный `Application` устанавливает обработчик uncaught exception. Он сохраняет обезличенные стековые кадры в Keystore-защищённую очередь, затем передаёт управление штатному crash handler. Следующий успешный запуск отправляет очередь.
- iOS: MetricKit принимает crash diagnostics и сохраняет только тип и позиции бинарных кадров. iOS доставляет MetricKit payload по своему расписанию, иногда после следующего запуска. Не все сбои доступны мгновенно.

Если процесс аварийно завершился до записи, закончилось место, сломано системное хранилище или произошёл аппаратный сбой, сохранение не гарантируется. До первого подключения к мосту отчёт остаётся на устройстве.

## Повторы и лимиты

На устройстве — до 100 отчётов, включая до 20 нативных crash payloads. Одинаковая ошибка в одном месте ограничивается одним отчётом в минуту. На мосте — до 500 агрегированных групп и 5000 ID для устранения повторных доставок.

Fingerprint учитывает версию, платформу, категорию, позицию в коде и операцию. Одинаковый fingerprint создаёт один GitHub Issue. Повторные события накапливают счётчик; обновления публикуются не чаще раза в час. Ограничение зеркалирования — 20 операций GitHub в день на запущенный мост. Пользовательские комментарии в Issue не перезаписываются, закрытые Issues автоматически не переоткрываются.

В `Настройки → Автоотчёты об ошибках` видно очередь телефона, группы на ПК, состояние доставки и ссылки на Issues. «Проверить отправку» создаёт явно помеченный диагностический тест, а не фиктивный баг.

## Отключить или сменить репозиторий

В приложении выключи **«Отправлять обезличенные отчёты»**. Новые события перестанут собираться, очередь устройства очищается. Уже доставленные Issues остаются в репозитории, их можно закрыть/удалить самостоятельно.

Только локальный сбор на ПК:

```sh
occ-pocket install --local-reports
```

Перезапусти OpenCode после изменения настройки. Для временного отключения GitHub: `OCC_REPORTS_GITHUB=0` в окружении моста. Свой репозиторий: `OCC_REPORTS_REPOSITORY=owner/repo`. В `bridge.json` эти настройки представлены `reportsGithub` и `reportsRepository`.

Обычное прямое подключение к OpenCode не содержит endpoint OCC-отчётов. Для доставки нужен OCC-мост. Нет постоянного общего облачного коллектора: авторизация и доставка выполняются тем компьютером, к которому подключён клиент.

## Как читать и исправлять

```sh
gh issue list --repo HVHBIGNAME/OpenCodePocket --label occ-client-report --state open
gh issue view NUMBER --repo HVHBIGNAME/OpenCodePocket --comments
```

Автоматические отчёты можно читать этими же инструментами в следующей coding-сессии, находить исходное место по версии/кадрам, воспроизводить сбой и привязывать исправление к Issue. Агент не мониторит репозиторий между запусками сам по себе.
